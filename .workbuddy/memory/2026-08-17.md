# 2026-08-17

## Skill Manager 桌面应用（v0.1 dev 已跑通）

在 `/Users/caozeal/projects/github/skill-manager` 从零搭建了 Tauri 2 + React 18 + TS 桌面应用，管理各 AI agent 挂载的 skill。

**关键架构事实（本机）**：
- 中央技能仓 `~/.agents/skills/`（22 个技能），锁文件 `~/.agents/.skill-lock.json`（v3，npx skills CLI 维护，格式 `{version, skills: {folder: {source, sourceType, sourceUrl, skillPath, installedAt, updatedAt}}}`）
- 各 agent 通过相对符号链接（如 `../../.agents/skills/x`）挂载中央仓技能
- SKILL.md frontmatter 全 agent 统一（name + description）；已用脚本验证 55/56 可解析，唯一异常 `api-test-workspace` 无 SKILL.md
- **Codex 技能语义（用户确认）**：用户级全局技能官方推荐位置 = `~/.agents/skills`（直接生效，无需符号链接）；`~/.codex/skills` 仅放内置(`.system`)与本地安装技能（当前仅 .system + hatch-pet）。已在 codex adapter note 与 README 中注明
- **全局技能合并功能（用户需求）**：AgentAdapter 新增 `global_skills_source` 字段（codex = Some("agents-central")），`scan_agent` 自动合并源仓库技能并标记 `is_global`；Skill 模型新增 `isGlobal`。UI：全局徽标（紫色 Globe2）、矩阵页全局紫点 + 图例、全局技能禁编辑/卸载。实测 codex 本地 2 个 + 全局 21 个，无重复。副作用：codex 页「挂载技能」按钮自动消失（全局技能直接生效，语义正确）
- **DSH 同样挂载全局目录（用户需求）**：dsh 从 Informational 改为 Standard + `global_skills_source: Some("agents-central")`（skills_path=None, read_only=true）。矩阵页过滤条件改为 `a.exists || a.skillCount > 0`（使 DSH 出现为列）；AgentPage 对无本地目录 agent 显示「全局技能来源: ~/.agents/skills」+「N 个全局技能（中央仓库直接生效）」，不显示「目录不存在」误导警告（该警告加了 agent.skillsPath 条件）。「只读展示」区块现仅剩 OpenCode
- **Kimi Code 也是全局机制（用户确认）+ scan_skills bug 修复**：kimi-code 加 `global_skills_source: Some("agents-central")`（本地 29 项含 6 个中央仓符号链接 + 15 个全局技能合并，本地同名去重）。**重要 bug**：`scan_skills`/`scan_all_skills` 命令里 `if !agent.has_skills_dir { continue/return }` 会跳过 DSH 这类无本地目录 agent 的全局技能合并 → 技能列表页/矩阵页为空；已移除该判断，直接走 `scanner::scan_agent`（内部对无目录 agent 返回空本地列表但仍合并全局）。各 agent 中央仓加载情况实测：符号链接挂载 = claude 14 / codebuddy 7 / kimi 6 / openclaw 4 / grok 3；全局机制 = codex / dsh / kimi；omp 无；wechat-markdown-publisher 最终解析到 ~/projects/github/my-openclaw-skill（本地项目技能）
- **OpenCode 三目录技能发现（用户确认）**：opencode 从 Informational 改为 Standard，新增 `compat_skills_source` 概念（区别于 global）：AgentAdapter 加 `compat_skills_source: Option<&'static str>`，opencode = Some("claude")；Skill 模型加 `is_compat`。scan_agent 合并顺序：本地 → global(紫) → compat(青)，统一 seen 去重。opencode 实测：本地 0 / 全局 21 / Claude 兼容 15 / 共 36。UI：青色「Claude 兼容」徽标（Layers 图标）、矩阵青色点 + 图例、AgentPage 统计三分类、兼容技能禁编辑/卸载。opencode read_only=true（不主动挂载，~/.config/opencode/skills 目录可能尚不存在）。informational 现已无 agent（区块代码保留无害）
- dev 技巧：tauri dev 残留的 vite 会占 1420 端口，重启用 `lsof -i :1420` 找 cwd 为本项目的 node 进程 kill 掉

**技术决策**：
- 所有文件系统操作走自定义 Rust command（不用 tauri-plugin-fs，免 scope 配置）
- `opener:default` 权限已含 `allow-reveal-item-in-dir`，前端直接调 `revealItemInDir`
- 矩阵页用后端 `scan_all_skills` 一次性拉全量，避免前端动态 hook 数量问题
- 安全规则：只删符号链接、.system/DSH/OpenCode 只读、不读含密钥配置文件、lock 只读

**已完成**：10 个 agent 注册表、扫描（真实/符号链接/断链检测）、frontmatter 编辑带备份、挂载/卸载、矩阵视图、全局搜索、详情抽屉。`npm run tauri dev` 正常运行，`cargo check`/`tsc` 全绿。

**Release 打包**：`npm run tauri build` 成功产出 `src-tauri/target/release/bundle/macos/Skill Manager.app`（6.1MB，ad-hoc 签名 arm64），但 **dmg 打包失败**：bundle_dmg.sh 的 AppleScript 美化步骤需要 Finder 自动化权限，后台 shell 环境返回 -10004 权限违例。用户在交互式终端重跑 `npm run tauri build` 会弹权限框，允许后即可生成 dmg（或直接把 .app 拖入 /Applications 使用）。
