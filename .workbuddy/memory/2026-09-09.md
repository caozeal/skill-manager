- Cargo 现有依赖无 `toml`/`toml_edit`，实现时需加。

分期建议：P0 只读盘点+启停（低风险）→ P1 增删改+跨 agent 同步 → P2 探活+技能↔MCP 依赖校验。

## 修复：codex / grok 的 MCP 完全不显示（TOML 源被两层取 key 吃空）

- 现象：MCP 页面只有 claude 3 + opencode 1，codex（应有 6）和 grok（应有 1）一条都没有。
- 根因：`mcp.rs::read_section` 里 TOML 分支已经把 `root` 设成 **mcp 段本身**（name->cfg 映射），
  但函数末尾仍按 JSON 的方式 `m.get(def.key)` 再取一次 `"mcp_servers"` → 永远 None → 空集合。
  JSON 分支 root 是整个文档，所以那样取是对的；TOML 分支被复用错了。
  更糟的是 `scan_all` 里 `let Ok(sec) = read_section() else { continue }` 把错误静默吞掉，页面毫无提示。
- 修复：
  - `read_section` 拆清语义——两个分支都统一返回「mcp 段」映射，末尾不再二次取 key。
  - `scan_all` 读取失败不再静默，改为 `eprintln!("[mcp] 读取 {agent} ({path}) 失败: {e}")`。
  - `to_server` 中 enabled 字符串比较改 `eq_ignore_ascii_case("false")`（TOML 里可能写 "False"）。
- 回归测试：`toml_section_reads_subtables`（内联 TOML 子表解析）+ `scan_real_config_finds_toml_agents`
  （真实配置冒烟：codex 配置存在就必须扫到条目）。修复后实测 11 条：claude 3 / codex 6 / grok 1 / opencode 1。
- 教训（通用）：**解析分支持平后要检查后续公共代码是否对两类输入都成立**；
  静默 `continue`/`unwrap_or_default` 是这类 bug 的帮凶，至少要留日志。

## 放开 OpenCode MCP 写入：JSONC 段落级原地替换

- 起因：老曹问「opencode 的 mcp 为什么不能禁用/删除」。原设计为了保注释把整个 JSONC 源设为只读——**过度保守**。
  查真实文件 `~/.config/opencode/opencode.jsonc`：**根本没有注释**，只有尾逗号（每对象最后一项都带 `,`）。
- 正解（与 TOML 用 toml_edit 同思路）：不大规模重写整个文件，做**段落级原地替换**。
  新函数（`src-tauri/src/mcp.rs`）：
  - `find_member_range(text, key)`：自己的轻量扫描器（跟踪字符串/转义 + 括号深度），
    在根层级定位 `"mcp": {...}` 的字节范围。没用 serde_json 是因为它拿不到原文位置。
  - `match_brace` / `has_comment`（只在字符串外找 `//`、`/*`，URL 里的 `//` 不算）。
  - `jsonc_value(v, indent)`：按 opencode 风格序列化——两空格缩进、每个成员后带尾逗号。
  - `write_jsonc_section(path, key, servers)`：替换该段；**段内有注释则返回 ReadOnlyAgent 拒绝**，
    没有该段时插到根对象最后一个 `}` 之前（支持给 opencode 新增 MCP）。
  - `line_indent_before`：沿用原文件缩进。
- SourceDef：opencode 的 `writable` 改 true（`native_enabled` 仍 false → 禁/启用走影子文件）。
- 前端：`MCP_WRITABLE_AGENTS` 加 `"opencode"`。
- 测试（12 个全过，新增 3 个）：
  `jsonc_write_only_touches_mcp_section`（注释/其它段必须原样）、
  `jsonc_write_refuses_commented_section`（段内有注释→拒绝且文件不变）、
  `real_opencode_jsonc_roundtrip`（拿真实文件复制到 /tmp 做读→写回，断言除 mcp 外所有顶层 key 不变）。
- 教训：**「文件格式有风险」不等于「整个源必须只读」**，先看清实际内容（有注释吗？有尾逗号吗？），
  能用「只重写目标段」把风险控制在一个局部就别一刀切。
